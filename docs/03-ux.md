# 3280 Kiosk — UX & Interaction Design

> **Status: CONCEPT / v1 UX.** The interaction model and screen deck we're
> building toward. The deck below formalizes the content Rick Lewis approved in
> the concept app (`src/kiosk-app/`) for the installed, three-button piece.

**Reads with:** `01-prd.md`, `02-architecture.md`. Cites PRD IDs where relevant.

**Design principles:** one obvious action at a time; nothing to learn; readable
across the gallery; resets itself for the next person; the *machine* is the hero,
the screen is its label.

---

## 1. The controls — three buttons, no modes

Physical, left-to-right, labeled to match the screen:

| Button | Always does | At a boundary |
|---|---|---|
| ◀ **BACK** | Previous screen | Inert + dimmed on Home (nothing before it) |
| ⌂ **HOME** | Jump to the Home summary | Always active |
| **NEXT** ▶ | Next screen | Inert + dimmed on the last screen |

- **No hidden gestures, long-press menus, or modes** in v1. What you see is all
  there is. *(FR2)*
- A **spare button is wired for "More"** (§5) but unpopulated in v1. *(FR5, ER3)*
- **Press feedback:** each press gives an immediate on-screen response (screen
  advances, or the dimmed button flashes to say "end of the line"). No dead presses.

---

## 2. Screen anatomy (portrait)

Every screen shares one skeleton so visitors learn it once:

```
┌───────────────────────────────┐
│  EYEBROW (what this is)        │  ← small, uppercase, amber
│                                │
│  HEADLINE                      │  ← the one idea, big, balanced
│  optional subhead              │
│                                │
│  ┌───────────────────────────┐ │
│  │        GRAPHIC            │ │  ← one strong image, fills width
│  └───────────────────────────┘ │
│                                │
│  • bullet one                  │  ← 3–5 short bullets, big
│  • bullet two                  │
│  • bullet three                │
│                                │
│                                │
│  ◀ Back    ⌂ Home    Next ▶    │  ← on-screen hints, aligned over
└───────────────────────────────┘     the real buttons below the glass
```

- **One idea per screen.** Headline states it; bullets support it; graphic proves
  it. *(CR1)*
- **Button hints sit at the bottom**, directly above the physical buttons, so the
  mapping is obvious to a first-timer. Dimmed hint = inert at this boundary.

## 3. Legibility spec (readable at 3–6 ft)

Targets for a portrait ~24″ panel at ~1080 px wide (scale with the actual panel):

| Element | Min size | Notes |
|---|---|---|
| Headline | ~64 px / 6 cqw+ | `text-wrap: balance`, 2 lines max |
| Subhead | ~36 px | one line |
| Bullets | ~34 px | 3–5 max, one line each where possible |
| Eyebrow / labels | ~22 px | uppercase, letter-spaced |
| Button hints | ~26 px | mirror physical labels |

- **Sans-serif throughout** (Archivo family in the app). *(CR1)*
- **Contrast:** high; never encode meaning in color alone. *(A2)*
- **Line length** and generous spacing so it reads at a glance, not a paragraph to
  study. *(CR2, CR3)*

## 5. "More detail" (spare button — designed, inert in v1)

Keeps Rick's deep-dive idea inside the no-touch model:

- Screens that have more to say show a small **"✚ More"** hint over the spare
  button (see the deck's *More?* column).
- **MORE** pushes a single detail screen (same skeleton, more depth); **BACK**
  returns to the main screen; **HOME** exits to Home; **NEXT** continues the main
  deck. One level deep only — no nested menus. *(FR5)*
- **v1:** the hint is hidden and the button unmapped; the content slots exist so
  turning it on later is data + one button mapping, no redesign. *(ER3, arch A4.3)*

## 6. States & attract

```
   power on
      │
      ▼
 ┌─────────┐  Next/Back      ┌──────────┐
 │  HOME   │ ───────────────►│ BROWSING │
 │(attract)│ ◄─────────────  │  deck    │
 └─────────┘   Home / idle   └──────────┘
      ▲              idle timeout │
      └──────────────────────────┘
```

- **Attract = the Home screen** with a gentle **"Press Next ▸"** pulse to invite a
  first press. No separate attract video (keeps it simple, silent, on-message).
- **Idle → Home.** After **~75 s** with no press, return to Home so the next
  visitor starts fresh. Long enough for a slow reader on a single screen, short
  enough to reset between groups. Configurable. *(FR3, A3)*
- **Silent throughout** — no audio anywhere. *(PRD non-goal)*

## 7. First-time clarity

A visitor walks up cold and must "get it" in seconds:

- Home says the whole point in **one headline** ("designed and built in New
  Jersey").
- The **pulsing "Press Next"** + button hints directly above the physical buttons
  tell them what to do without instructions.
- Three buttons, clearly labeled, is the entire interface — nothing to discover.

---

## 8. Accessibility (UX side)

- **Reach:** button hints align to physical buttons placed in the ADA reach range;
  if the door position can't satisfy reach, a separate low plate is the fallback.
  *(A1, arch A8.5)*
- **Readable:** §3 sizes, high contrast, no color-only meaning. *(A2)*
- **Forgiving:** any state is one **HOME** press from the start; idle reset covers
  walk-aways; no timed content a slow reader can miss. *(A3)*
- **Simple mental model** for all ages/abilities: three labeled buttons, one idea
  per screen. *(A3)*
